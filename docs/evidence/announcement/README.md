# Announcement preview and recording rehearsal

The `announcement` example reuses gallery `Dialogs`, retained Dropdown/Input/Dialog state and native Toast feedback. It hides diagnostic controls only in this focused host; the standard gallery retains them. No versions/vendor changes. Run `cargo run -p kumo-gallery --example announcement --locked`; add `-- --dark` or `-- --width=520` to review those states. Switch theme updates an existing Toast.

The actual native Linux Light/Dark1040/520 matrix in `linux/results.json` passes menu pointer → modal editor/initial focus → save → nonmodal feedback, surviving menu trigger restoration, live theme change with feedback retained, alert confirmation and delete feedback. PNGs/logs capture idle/menu/editor/save/theme/delete states. Review action centres/baselines, narrow wrapping and nested corner/ring/shadow alignment. Source component contracts remain in the Dropdown/Dialog/Toast validation documents; a bespoke preview composition has no separate browser application counterpart.

`probe.py` reproduces the matrix and captures a Linux rehearsal to `/workspace/artifacts/gpui-kumo-announcement-rehearsal.mp4` with FFmpeg x11grab/H.264,1040×800,30fps, no audio. It uses real pointer/keyboard/AT-SPI paths, not a simulated animation. The movie is a local artifact; source/scripts/evidence are committed, generated video is outside Git. FFmpeg shuts down through stdin `q` so file finalization is checked normally.

Full pinned gate is in `rust-gate.log`:226library/1gallery/9doctests, adapter12/14, fmt/warnings-denied Clippy and locked builds. Toast core94351f4 also passes [macOS37138801443](https://github.com/msmps/gpui-kumo/actions/runs/37138801443). The preview's published SHA/CI result is recorded separately after push.

This is a **Linux rehearsal**, not macOS visual acceptance or a published announcement.
