# Readable Label evidence

Linux X11/software Vulkan, pinned Kumo3fd5b648, Kit/Base0.7.0 and GPUIpre0.3.7; gallery baseline d195ded plus the standalone optional Label sample. `before.json` and `after.json` are actual native AT-SPI measurements. `geometry-comparison.json` compares all143 ordered Label bounds in each light/dark1040/520 combination: unchanged bounds,139 unnamed before and zero afterward, all nine sampled names present after, explicit heading preserved.

Text/Field/Banner/Badge/Breadcrumb captures show actual painted themes and wide/narrow layouts. Capture procedure moves the window to0,0, returns to the visible theme controls before switching, then scrolls each named sample into view. Native default window position otherwise makes window-relative bounds unsuitable as desktop pointer coordinates. Initial dark filenames with light paint were rejected and overwritten. Alignments, baselines, padding, corners/fills/borders/rings/layers are reviewed separately from metadata.

These are native metadata/layout/paint observations, not proof of screen-reader speech, IME, browser pixel identity or macOS/Windows behavior. The pre-existing highlighted Text font question remains [#38](https://github.com/msmps/gpui-kumo/issues/38). See [acceptance/results](../../readable-label-validation.md).
