# Tabs core contract and acceptance

Pinned Kumo `3fd5b648df578cb1ba214dedd30f475009f6a668` Tabs source, complete tests, documentation and demos were inspected alongside installed Base0.7.0 Tab/TabList. The source supports segmented/underline, base/sm and horizontal navigation; deprecated MenuBar is excluded. Source styling constants describe older geometry: this slice follows current class recipes (36/26px segmented,30/26px underline,14/12px text), subject to remaining browser measurement below.

| Contract | Native core checkpoint |
| --- | --- |
| Identity/content | Typed `TabItem<T>`, stable IDs and unique values; complete readable names, optional decorative content factory. Retain child entities outside rendering and capture owners weakly. |
| Ownership | Caller retains one `Entity<TabsState<T>>` per mounted list. Uncontrolled state applies user changes; controlled state emits `TabsEvent<T>` proposals and waits for silent `set_selected` acceptance. Modes are chosen at construction. No second owner value is maintained in uncontrolled mode. |
| Activation | Base Tab supplies pointer, Enter/Space and accessibility click. Current availability/value are read at activation, repeated selection emits nothing. Pointer activation focuses its tab before keyboard continuation. |
| Navigation | Left/Right wrap and skip disabled; Home/End choose first/last enabled. Default manual activation separates focus from selection; `activate_on_focus(true)` proposes on navigation. Modified keys and vertical arrows are left to the host. |
| Focus | Retained per-ID handles survive reorder; one enabled tab stop per list, selected/focused/first fallback. Removed or newly unavailable focused items transfer to the remaining selected/first enabled item, or traverse forward if empty. Programmatic collection/value updates emit no user proposal. |
| Availability | Per-item/group disabled gates all input, removes traversal entry and authors disabled on Base's actual tab node. Existing focus remains until traversal or collection replacement; no focus theft on a group availability update. |
| Presentation | Both variants/sizes use Kumo theme tokens, static selected surface/underline and keyboard ring. Border/ring paint does not move labels when focus/selection changes. Native horizontal overflow and nearest focused-tab reveal work. |
| Meaning | Base TabList and Tab roles, names, selected state and set position/size. Native AT-SPI observes selection, disabled availability and focus. Speech is a separate gate. |
| Panels/orientation | Source Kumo exports no panel/mount API or orientation prop; panels and focus inside content are consumer-owned, vertical orientation is N/A for this source wrapper. No inferred TabPanel API is exported. |
| Web replacement/links | DOM `render`, `nativeButton`, CSS classes and browser navigation are not copied as Rust flags. Decorative content is available; a complete native replacement/navigation composition contract remains open. |

The focused example imports the gallery's actual Tabs section. [Native evidence and reproduction](evidence/tabs/README.md) covers Light/Dark1040/520 and real pointer, keyboard and AT-SPI paths. Three rendered regressions cover manual/automatic selection, rejected and silent accepted controlled proposals, disabled skipping, host traversal, repeated independent instances, reorder, removal and empty-list focus. Event subscriptions are checked after the GPUI update flush, rather than assuming synchronous `cx.emit` delivery. Base's internal headless observation is installed after its caller-supplied focus binding, so tests inspect the retained handle's actual window focus; native AT-SPI supplies the independent exported-focus check.

Skeptical review caught missing TabStop registration on explicitly tracked handles: setting only an element's `tab_stop` does not alter its supplied FocusHandle in this GPUI revision. The wrapper now passes configured clones of retained handles, and the tests verify traversal **into** the list as well as exit. No vendor change was necessary. Per-list nested tab groups reordered unrelated sibling Buttons in the selected GPUI traversal model; they were removed and repeated-list/native traversal now exercise the shared host ordering.

**Open under #32:** source overflow edge buttons/fades, drag-to-scroll with click suppression,200ms sliding indicator/reduced-motion fidelity, browser-measured geometry/ring/shadow parity, native replacement/link composition, full-gallery integration review, dynamic overflow stress and platform speech gates. The current indicator is static and focus rings are painted within tab bounds. Arbitrary rich descendant clipping is not accepted by this checkpoint. Core coverage counts as one working family; this is not full supported API/fidelity completion and the issue remains open. Complete overflow/motion next, then choose the next dependency-ready family.
