## Implementation notes

`Input::label_tooltip(&retained_tooltip, text)` and `InputGroup::label_tooltip` reuse Label/Tooltip directly. These builders do not enable a hidden label implicitly. Removed/replaced help cancels old disclosure; hidden labels and empty help close pending/open state. Caller retains each TooltipState and mounts TooltipProvider around participating focusables. No editor/value mirror or subscription is added.

Native review also exposed built-in labels/helpers falling back to different visible typography. Installed CosmicText matches literal family names and does not resolve CSS `sans-serif`. Component overrides did not demonstrate a repair and were removed. Central Linux default now uses the concrete installed DejaVu Sans family: native fresh-start/theme/narrow renders show consistent sans typography; macOS/Windows mappings remain unchanged. Noto Sans trial did not remove the visible fixture discrepancy, so it was not selected on source inspection alone. If DejaVu Sans is absent, GPUI can fall back; consumers must install the configured family or choose an available family with Theme::with_font_family and validate native weight/glyph rendering. Font/platform fidelity beyond this host remains unverified.
